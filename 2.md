### Пункт 7: Оптимизация обновления списка заявок

#### Реализованные изменения:

1. **Добавлено поле в класс ChatMessages** (строка ~82):
   - `private Integer pendingListMessageId;` - для хранения ID сообщения со списком
   - Добавлены методы: `getPendingListMessageId()` и `setPendingListMessageId(Integer id)`

2. **Модифицирован метод handlePendingCommand** (строка ~612):
   - Добавлено сохранение ID сообщения при отправке пустого списка
   - Изменено использование `executeAndTrack()` на `execute()` для получения объекта Message
   - Добавлено сохранение ID в ChatMessages через `computeIfAbsent()`
   - Сохраняется как `pendingListMessageId`, так и `lastWindowMessageId`

3. **Добавлен новый метод updatePendingListIfNeeded** (строка ~745):
   - Проверяет наличие сохраненного ID списка
   - Если ID есть - редактирует существующее сообщение через `EditMessageText`
   - Если ID нет или редактирование не удалось - отправляет новый список
   - Полностью копирует логику формирования списка из `handlePendingCommand`
   - Содержит fallback механизм при ошибке редактирования

4. **Модифицирован метод handleModCancelConfirm** (строка ~2260):
   - Заменен вызов `handlePendingCommand(chatId)` на `updatePendingListIfNeeded(chatId)`
   - Остальная логика удаления сообщений сохранена

#### Преимущества:
- ✅ Список обновляется на месте без отправки нового сообщения
- ✅ Плавный UX без "мигания" чата
- ✅ Оптимизация трафика Telegram API
- ✅ Fallback механизм при ошибках

## Потенциальные проблемы и решения

### Проблема: Telegram API не позволяет удалить старые сообщения
**Решение**: Все вызовы `execute(deleteMsg)` обернуты в try-catch с логированием ошибок.

### Проблема: Сообщение со списком было удалено вручную
**Решение**: В `updatePendingListIfNeeded` при ошибке редактирования вызывается `handlePendingCommand` для отправки нового списка.

### Проблема: Конкурентный доступ к chatMessages
**Решение**: Используется `computeIfAbsent` для атомарного создания объекта ChatMessages.
