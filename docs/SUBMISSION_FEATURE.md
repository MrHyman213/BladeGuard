# Функционал заявок на сертификаты

## Описание

Добавлена система заявок, позволяющая пользователям предлагать новые сертификаты, а администраторам - управлять этими заявками.

## Структура БД

### Таблица `submissions` (заявки)
- `id` - уникальный идентификатор
- `user_id` - ID пользователя Telegram
- `username` - имя пользователя Telegram
- `photo_path` - путь к фото на Яндекс.Диске (в папке `/certificates/offer`)
- `user_description` - описание от пользователя
- `admin_description` - описание от администратора
- `status` - статус заявки (PENDING, APPROVED, REJECTED)
- `created_at` - дата создания
- `updated_at` - дата обновления

### Таблица `tags` (теги)
- `id` - уникальный идентификатор
- `name` - название тега (уникальное)
- `created_at` - дата создания

### Таблица `submission_tags` (связь заявок и тегов)
- `submission_id` - ID заявки
- `tag_id` - ID тега

### Таблица `certificates` (сертификаты)
- `id` - уникальный идентификатор
- `submission_id` - ID заявки (опционально)
- `photo_path` - путь к фото
- `description` - описание
- `created_at` - дата создания

### Таблица `certificate_tags` (связь сертификатов и тегов)
- `certificate_id` - ID сертификата
- `tag_id` - ID тега

## Функционал для пользователей (KnifeBot)

### Команды:
- `/start` - показать список команд
- `/list` - показать список фотографий
- `/get <имя_файла>` - получить фотографию
- `/submit` - подать заявку на добавление сертификата
- `/skip` - пропустить добавление описания к фото

### Процесс создания заявки:
1. Пользователь отправляет фото боту
2. Фото загружается в папку `/certificates/offer` на Яндекс.Диске
3. Бот предлагает добавить описание
4. Пользователь может:
   - Отправить текстовое описание
   - Использовать `/skip` для пропуска описания
   - Сразу отправить фото с подписью (caption)

## Функционал для администратора (AdminBot)

### Команды:
- `/start` - показать список команд
- `/pending` - показать все заявки на рассмотрении
- `/view <id>` - просмотреть заявку с фото
- `/desc <id>` - добавить/изменить описание администратора
- `/tags <id> <тег1,тег2>` - добавить теги к заявке
- `/approve <id>` - одобрить заявку
- `/reject <id>` - отклонить заявку

### Процесс обработки заявки:
1. Админ просматривает список заявок через `/pending`
2. Просматривает конкретную заявку через `/view <id>`
3. Добавляет/редактирует описание через `/desc <id>`
4. Добавляет теги через `/tags <id> тег1,тег2,тег3`
5. Одобряет или отклоняет заявку

## Примеры использования

### Пользователь создает заявку:
```
Пользователь: [отправляет фото]
Бот: ✅ Фото загружено!
     Теперь отправьте описание или отправьте /skip чтобы пропустить.
Пользователь: Нож охотничий, сталь 95Х18
Бот: ✅ Заявка успешно создана с описанием!
```

### Админ обрабатывает заявку:
```
Админ: /pending
Бот: 📋 Заявки на рассмотрении:
     ID: 1
     От: @username
     Описание: Нож охотничий, сталь 95Х18
     Дата: 2026-02-26T10:30:00

Админ: /view 1
Бот: [отправляет фото с полной информацией]

Админ: /desc 1
Бот: Отправьте новое описание для заявки #1
Админ: Охотничий нож "Медведь", сталь 95Х18, рукоять из карельской березы
Бот: ✅ Описание обновлено для заявки #1

Админ: /tags 1 охотничий,95х18,береза
Бот: ✅ Теги добавлены к заявке #1

Админ: /approve 1
Бот: ✅ Заявка #1 одобрена
```

## Технические детали

### Новые зависимости в pom.xml:
- `spring-boot-starter-data-jpa` - для работы с БД
- `postgresql` - драйвер PostgreSQL
- `liquibase-core` - для миграций БД

### Новые классы:
- `entity/Tag.java` - сущность тега
- `entity/Submission.java` - сущность заявки
- `entity/Certificate.java` - сущность сертификата
- `repository/TagRepository.java` - репозиторий тегов
- `repository/SubmissionRepository.java` - репозиторий заявок
- `repository/CertificateRepository.java` - репозиторий сертификатов
- `service/SubmissionService.java` - сервис для работы с заявками

### Изменения в существующих классах:
- `YandexDiskService.java` - добавлен метод `uploadPhotoToOffer()` для загрузки в папку offer
- `KnifeBot.java` - добавлена обработка заявок
- `AdminBot.java` - добавлены команды для управления заявками

## Запуск

```bash
# Убедитесь, что в .env заполнены все переменные
docker-compose up -d

# Или для локальной разработки
mvn spring-boot:run
```
