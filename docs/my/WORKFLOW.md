# Blade Guardian — Сценарий работы приложения

Версия: 1.0  
Обновлено: 06.03.2026

---

## 🎯 Запуск приложения

### При старте приложения:
1. **Spring Boot** загружает конфигурацию из `.env` и `application.properties`
2. **Liquibase** применяет миграции базы данных
3. **YandexDiskInitializer** проверяет папки на Яндекс.Диске:
   - `app:/offers/` — заявки на модерацию
   - `app:/certificates/` — одобренные сертификаты
   - `app:/archive/replaced/` — архив заменённых фото
4. **KnifeBot** и **AdminBot** подключаются к Telegram API
5. Приложение слушает обновления на порту **8080**


### 3. Выбор модели (просмотр сертификата)

```
Пользователь нажимает: [Swiss Army Knife]
```

**Что происходит:**
- Загружается сертификат из `submissions` (статус `APPROVED`)
- **Проверяется наличие фото на Яндекс.Диске**
- Загружаются альтернативы **только если у них есть фото на диске**
- Отправляется сообщение с фото и кнопками

**Вид сертификата:**
```
┌─────────────────────────────────────┐
│  [📷 Фото сертификата]              │
│                                     │
│  Victorinox — Swiss Army Knife      │
│  Индекс: SAK-001                    │
│                                     │
│  ──── Альтернативы ────             │
│ [Victorinox — Climber (inline btn)] │
│  [Victorinox — Huntsman]            │
│  [Больше...] (если > 2 и есть фото) │
│                                     │
│  [🔙 Назад]                         │
└─────────────────────────────────────┘
```

**Важно:** 
1. Альтернативы отображаются **только** если у сертификата альтернативы имеется файл фото на Яндекс.Диске (`photo_path != null`).
2. В базе не может быть модели, у которой нет ни файла фото на Яндекс.Диске (`photo_path != null`), ни единой связи в таблице с альтернативами (submission_alternatives). 
3. В случае удаления строки, у которой имеется сертификат и связи в таблице с альтернативами - удалить те модели ножей, у которых нет ни фото, ни других связей, кроме этой. ***Тоесть моделей ножей без связей в альтернативах и без пути к фото на диске, быть не должно***.

### 4. Загрузка сертификата

```
Пользователь нажимает: [📤 Загрузить]
```

**Что происходит:**
- Отправляется справка о формате загрузки
- Пользователь отправляет фото (с caption или без)
- **Сообщение пользователя удаляется**
- Если caption в формате `Бренд / Название / Индекс`, `Бренд / Название` или `Название` — поля заполняются автоматически
- Открывается **форма редактирования**

**Вид формы:**
```
┌─────────────────────────────────────┐
│  📝 Форма загрузки                  │
│                                     │
│  [🏷️ Бренд: Victorinox] (inline btn)│
│  [📝 Название: Swiss Army Knife]    │
│  [🔢 Индекс: SAK-001]               │
│                                     │
│  ──── Альтернативы ────             │
│  [❌ Victorinox — Climber]          │
│  [➕ Добавить альтернативу]         │
│                                     │
│  [✅ Загрузить] [❌ Закрыть]        │
└─────────────────────────────────────┘
```

**Изменение значения поля**
```
Пользователь нажимает на [🔢 Индекс: SAK-001]
```
1. Выводится справка формата:
Текущее значение индекса: `SAK-001`
Отправьте новый значение индекса. 
2. Пользователь отправляет сообщение "SD-03"
3. Справка и сообщение от пользователя удаляется. В форме загрузки редактируется inline-кнопка "Индекс".  

**Добавление альтернативы:**
1. Нажать `[➕ Добавить альтернативу]`
2. Ввести: `Victorinox / Classic SD`. Так же можно и несколько формата `Бренд / Название, Бренд / Название, Название`
3. Альтернатива сохраняется в `pending_alternatives`

**Отправка на модерацию:**
1. Нажать `[✅ Загрузить]`
2. **Сообщение с формой удаляется**
3. Фото загружается в `app:/offers/`
4. Данные сохраняются в `submissions` (статус `PENDING`)
5. Альтернативы сохраняются в `pending_alternatives`
6. Пользователь видит: *"✅ Спасибо! Ваша заявка отправлена на модерацию."*
7. Сообщение удаляется, при любом действии пользователя

**Отмена загрузки:**
1. Нажать `[❌ Закрыть]`
2. Подтверждение: `[✅ Да]` - **Все сообщения удаляются** / `[❌ Нет]` - удаление подтверждения.
3. Пользователь возвращается в главное меню

## 🔍 Анализ диска

### Проверка соответствия путей
- Сравниваются пути в БД (`submissions.photo_path`) и на Яндекс.Диске
- Ищутся битые ссылки (файл не существует)

### Ложные срабатывания
**Проблема:** Анализ может показывать 2 раза `certificates` при подсчёте непривязанных фото.

**Причина:** Файлы в `app:/certificates/` могут дублироваться в подсчётах из-за:
1. Проверки обеих папок (`offers` и `certificates`)
2. Отсутствия фильтра по статусу `APPROVED`

**Решение:**
```java
// Корректный подсчёт непривязанных фото
List<String> dbPhotoPaths = submissionRepository.findAllPhotoPaths();
List<String> diskFiles = yandexDiskService.getAllFiles("app:/");

// Фильтруем только файлы из certificates со статусом APPROVED
List<String> validPaths = dbPhotoPaths.stream()
    .filter(path -> path.startsWith("app:/certificates/"))
    .collect(Collectors.toList());

// Непривязанные = на диске - в БД
List<String> orphaned = diskFiles.stream()
    .filter(file -> !validPaths.contains(file))
    .collect(Collectors.toList());
```

### Вид отчёта анализа:
```
┌─────────────────────────────────────┐
│  🔍 Анализ диска                    │
│                                     │
│  📊 Статистика:                     │
│  • В БД: 150 сертификатов           │
│  • На диске: 152 файла              │
│  • Непривязанных: 2 файла           │
│  • Битых ссылок: 0                  │
│                                     │
│  Непривязанные файлы:               │
│  • app:/offers/old_photo.jpg        │
│  • app:/archive/replaced/old.png    │
│                                     │
│  [🗑️ Очистить битые ссылки]         │
|  [Очистить непривязанные ссылки]    |
│  [🔙 Назад]                         │
└─────────────────────────────────────┘
```

## 📝 Примечания

### Удаление сообщений
- **Пользователь:** Любое действие в форме удаляет сообщение
- **Администратор:** Ввод текста удаляет сообщение, форма обновляется

### Альтернативы
- Отображаются выбранной модели ножа **только при наличии фото** на Яндекс.Диске
- Pending альтернативы требуют подтверждения модератором
- Транзитивные альтернативы предлагаются автоматически

### История замен
- Кнопка отображается **только если были замены**
- Хранится в таблице `photo_history`
- Возможен откат к любой предыдущей версии

### Анализ диска
- Проверяет соответствие БД ↔ Яндекс.Диск
- Фильтрует по статусу `APPROVED` для certificates
- Игнорирует папку `app:/offers/` (временные файлы)
