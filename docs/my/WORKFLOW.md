## 🎯 Запуск приложения

### При старте приложения:
1. **Spring Boot** загружает конфигурацию из `.env` и `application.properties`
2. **Liquibase** применяет миграции базы данных
3. **YandexDiskInitializer** проверяет папки на Яндекс.Диске:
   - `app:/offers/` — заявки на модерацию
   - `app:/certificates/` — одобренные сертификаты
   - `app:/archive/replaced/` — архив заменённых фото
4. **KnifeBot** и **AdminBot** подключаются к Telegram API
5. Приложение слушает обновления на порту **8080**

### 3. Выбор модели (просмотр сертификата)

```
Пользователь нажимает: [Swiss Army Knife]
```

**Что происходит:**
- Загружается сертификат из `knives`
- **Проверяется наличие фото на Яндекс.Диске**
- Загружаются альтернативы **только если у них есть фото на диске**
- Отправляется сообщение с фото и кнопками

**Вид сертификата:**
```
┌─────────────────────────────────────┐
│  [📷 Фото сертификата]              │
│                                     │
│  Victorinox — Swiss Army Knife      │
│  Индекс: SAK-001                    │
│                                     │
│  ──── Альтернативы ────             │
│ [Victorinox — Climber (inline btn)] │
│  [Victorinox — Huntsman]            │
│  [Больше...] (если > 2 и есть фото) │
│                                     │
│  [🔙 Назад]                         │
└─────────────────────────────────────┘
```

**Важно:** 
1. Альтернативы отображаются **только** если у сертификата альтернативы имеется файл фото на Яндекс.Диске (`photo_path != null`).
2. В базе не может быть модели, у которой нет ни файла фото на Яндекс.Диске (`photo_path != null`), ни единой связи в таблице с альтернативами (submission_alternatives). 
3. В случае удаления строки, у которой имеется сертификат и связи в таблице с альтернативами - удалить те модели ножей, у которых нет ни фото, ни других связей, кроме этой. ***Тоесть моделей ножей без связей в альтернативах и без пути к фото на диске, быть не должно***.

### 4. Загрузка сертификата

```
Пользователь нажимает: [📤 Загрузить]
```

**Что происходит:**
- Отправляется справка о формате загрузки
- Пользователь отправляет фото (с caption или без)
- **Сообщение пользователя удаляется**
- Если caption в формате `Бренд / Название / Индекс`, `Бренд / Название` или `Название` — поля заполняются автоматически
- Открывается **форма редактирования**

**Вид формы:**
```
┌─────────────────────────────────────┐
│  📝 Форма загрузки                  │
│                                     │
│  [🏷️ Бренд: Victorinox] (inline btn)│
│  [📝 Название: Swiss Army Knife]    │
│  [🔢 Индекс: SAK-001]               │
│                                     │
│  ──── Альтернативы ────             │
│  [❌ Victorinox / Climber]          │
│  [➕ Добавить альтернативу]         │
│                                     │
│  [✅ Загрузить] [❌ Закрыть]        │
└─────────────────────────────────────┘
```

**Изменение значения поля**
```
Пользователь нажимает на [🔢 Индекс: SAK-001]
```
1. Выводится справка формата:
Текущее значение индекса: `SAK-001`
Отправьте новый значение индекса. 
2. Пользователь отправляет сообщение "SD-03"
3. Справка и сообщение от пользователя удаляется. В форме загрузки редактируется inline-кнопка "Индекс".  

**Добавление альтернативы:**
1. Нажать `[➕ Добавить альтернативу]`
2. Ввести: `Victorinox / Classic SD`. Так же можно и несколько формата `Бренд / Название, Бренд / Название, Название`
2.1 *Валидация* - Вид "brand/name" парсится по разным колонкам, не в одно название.
2.2 **Настройка разделителя** - модератор может настраивать символ, который будет отвечать за разделение по полям заявки (default = "/"). Значение хранится в .env, в поле `pattern`.
3. Альтернатива сохраняется в `pending_alternatives`

**Отправка на модерацию:**
1. Нажать `[✅ Загрузить]`
2. **Сообщение с формой удаляется**
3. Фото загружается в `app:/offers/`
4. Данные сохраняются в `submissions_buffer`
5. Пользователь видит: *"✅ Спасибо! Ваша заявка отправлена на модерацию."*
6. Сообщение удаляется, при любом действии пользователя

**Отмена загрузки:**
1. Нажать `[❌ Закрыть]`
2. Подтверждение: `[✅ Да]` - **Все сообщения удаляются** / `[❌ Нет]` - удаление подтверждения.
3. Пользователь возвращается в главное меню

### 5. Обработка альтернатив

**Ожидающие альтернативы** — это альтернативы, которые пользователь добавил при загрузке. Они хранятся в колонке `alternatives` таблицы `submissions_buffer` строкой формата `Бренд / Название, Бренд / Название`.

**Вид в форме:**
```
Альтернативы
[❌ Victorinox / Climber]
[❌ Victorinox / Huntsman]
[➕ Добавить альтернативу]
```

**Добавление альтернативы:**
1. Нажать `[➕ Добавить альтернативу]`
2. Ввести: `Victorinox / Classic SD`. Так же можно и несколько, формата `Бренд / Название, Бренд / Название, Название`
3. Альтернатива добавляется в строку `alternatives` таблицы `submissions_buffer`

### 6. Одобрение заявки

```
Администратор нажимает: [✅ Одобрить]
```

**Что происходит:**
1. Удаляется сообщение-форма заявки
2. Фото перемещается из `app:/offers/` в `app:/certificates/`
3. **Отправляется сообщение-оповещение о добавлении новых альтернатив в систему**

**Вид оповещения:**
```
┌─────────────────────────────────────┐
│  🔄 Найдены новые альтернативы:     │
│  • Victorinox / Climber             │
│  • Victorinox / Huntsman            │
│                                     │

│                                     │
│  [✅ Да, завершить] [❌ Отмена]     │
└─────────────────────────────────────┘
```

**После нажатия `[✅ Да, завершить]`:**
1. Создаются связи в `alternatives`
2. Проверяются транзитивные альтернативы
3. Если найдены — предлагается добавить
4. Пользователь получает уведомление
5. Если бренд новый — обновляются все главные меню

**Транзитивные альтернативы:**
```
┌─────────────────────────────────────┐
│  🔄 У ножа Victorinox / Huntsman    │
│  имеются ещё альтернативы:          │
│  • Test / ManF                      │
│                                     │
│  Добавить к сертификату             |
|  Test / Manf новые связи?           |
│                                     │
│  [✅ Да] [❌ Нет]                  │
└─────────────────────────────────────┘
```

**После нажатия `[✅ Да]` или [❌ Нет] (общее поведение):**
1. Удаляется сообщение-подтверждение.

**После нажатия `[✅ Да]`:**
1. Создаются связи в `alternatives` со стороны сертификата Huntsman - добавляются Victorinox / Climber, Brand / Swiss Army Knife Deluxe
2. Создаются связи в `alternatives` со стороны сертификата от @danil - добавляются Test / ManF, так же весь его список альтернатив.

## 🔄 Автоматические процессы

### Автообновление главного меню
- При добавлении нового бренда **все меню пользователей** обновляются
- Используется `UserMainMenuService.autoUpdateMainMenu(chatId, messageId)`

### Журнал ошибок
- Последние 50 ошибок сохраняются в памяти
- Доступны через `[📋 Журнал ошибок]`
- Очистка: `[🗑️ Очистить журнал]`

## 📝 Примечания

### Удаление сообщений
- **Пользователь:** Любое действие в форме удаляет сообщение
- **Администратор:** Ввод текста удаляет сообщение, форма обновляется

### Альтернативы
- Отображаются в выбранной модели ножа **только при наличии фото** на Яндекс.Диске
- Новые альтернативы требуют подтверждения модератором
- Транзитивные альтернативы предлагаются автоматически

---

### Форматы caption (3 варианта)

**Пользователь отправляет фото с caption:**

| Формат | Заполненные поля |
|--------|------------------|
| `Бренд / Название / Индекс` | Бренд ✅, Название ✅, Индекс ✅ |
| `Бренд / Название` | Бренд ✅, Название ✅ |
| `Название` | Название ✅ |

**Примеры:**
```
Victorinox / Swiss Army Knife / SAK-001  → Все 3 поля
Victorinox / Swiss Army Knife            → Бренд + Название
Swiss Army Knife                         → Только название
```

---

### Множественные альтернативы (через запятую)

**Формат ввода:**
```
Бренд1 / Название1, Бренд2 / Название2, Название3
```

**Примеры:**
```
Victorinox / Climber, Boker / Tree       → 2 альтернативы
Climber, Huntsman, Ranger                → 3 названия (бренд общий)
Victorinox / Classic SD                  → 1 альтернатива
```

## 🧪 Тестирование

### Пользовательский сценарий:
```
1. /start → Главное меню (сетка 10×3)
2. Выбор бренда → Список моделей
```
